# 安全例外登记

本文件记录**暂时无法按期修复**的依赖漏洞或其他安全例外。没有登记在这里的漏洞，
默认按 `docs/operations.md` 的时限处理，不视为已接受风险。

## 规则

- 每条例外必须填满六个字段；缺项视为未登记。
- `到期日` 使用 `YYYY-MM-DD`，最长不超过 90 天；到期未复核自动失效。
- 到期前一周由负责人复核：升级、重新审批续期，或删除例外并接受阻断。
- 补偿措施必须能实际降低风险（功能开关、网络限制、缩短凭证寿命等），
  不能只写“已知悉”“后续处理”。
- critical 例外必须由安全负责人 + 业务负责人双签；high 由模块负责人签。

## 字段说明

| 字段 | 填写要求 |
| --- | --- |
| 漏洞编号 | CVE / GHSA / npm advisory ID；同一组件多个编号可逗号分隔 |
| 影响组件 | `package@version`，并注明是 dependencies 还是 devDependencies |
| 接受理由 | 为什么现在不能升级（上游未修复、破坏性变更、运行时不可达等），要给可核验的事实 |
| 补偿措施 | 已落地的缓解手段及其验证方式；没有补偿措施就不能接受 |
| 到期日 | `YYYY-MM-DD`；到期未复核视为失效 |
| 负责人 | GitHub handle 或姓名，必须是具体的人，不能写团队名 |
